# Tool Registry

This registry begins with the ten flagship tools explicitly suggested in `CLAUDE.md`. The specification does not include tool-specific Implement/Avoid notes or enumerate the remaining M3/M4 entries; those are intentionally left undefined rather than guessed. Before authoring each page, verify official documentation and changelog details and expand the row with evidence-based notes.

| Category           | Tool            | Slug             | Seed for implementation                                                                                                                                                                                                                                                                                                                                                              |
| ------------------ | --------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| languages-runtimes | TypeScript      | `typescript`     | Implement: strict checks, validate unknown input, test boundaries. Avoid: unchecked assertions and assuming types validate runtime data. See the [official handbook](https://www.typescriptlang.org/docs/handbook/2/narrowing.html) and [7.0.2 release](https://github.com/microsoft/TypeScript/releases/tag/v7.0.2).                                                                |
| package-management | Bun             | `bun`            | Implement: pin Bun, commit its lockfile, use frozen CI installs and test runtime compatibility. Avoid: assuming a missing lockfile is created in frozen mode or that running TypeScript type-checks it. See [installation](https://bun.com/docs/pm/cli/install) and [runtime](https://bun.com/docs/runtime).                                                                         |
| frontend           | Astro           | `astro`          | Implement: static rendering, validated content collections, selective islands, and tested build output. Avoid: expecting static data to update without a rebuild or shipping build-time secrets. See [collections](https://docs.astro.build/en/guides/content-collections/) and [islands](https://docs.astro.build/en/concepts/islands/).                                            |
| styling-ui         | Tailwind CSS v4 | `tailwind-css`   | Implement: Vite plugin, CSS-first theme tokens and production CSS verification. Avoid: dynamic class fragments and assuming tokens ensure accessibility. See [theme](https://tailwindcss.com/docs/theme) and [source detection](https://tailwindcss.com/docs/detecting-classes-in-source-files).                                                                                     |
| testing            | Vitest          | `vitest`         | Implement: independent behavioral tests, explicit discovery and CI execution. Avoid: shared state, brittle implementation assertions and interpreting coverage as correctness. See [configuration](https://vitest.dev/config/) and [coverage](https://vitest.dev/guide/coverage).                                                                                                    |
| testing            | Playwright      | `playwright`     | Implement: isolated browser fixtures, user-facing locators, accessibility checks and CI browser installation. Avoid: fixed waits, shared state and treating automated scans as complete accessibility testing. See [best practices](https://playwright.dev/docs/best-practices) and [accessibility](https://playwright.dev/docs/accessibility-testing).                              |
| data               | PostgreSQL      | `postgresql`     | Implement: migrations, parameters, transactions, verified backups and monitoring. Avoid: SQL interpolation and treating embedded tests as server validation. See [transactions](https://www.postgresql.org/docs/18/tutorial-transactions.html) and [18.7 notes](https://www.postgresql.org/docs/release/18.7/).                                                                      |
| ci-cd              | GitHub Actions  | `github-actions` | Implement: least-privilege workflows, pinned actions, concurrency and protected deployment credentials. Avoid: privileged execution of untrusted pull requests or shell interpolation. See [secure use](https://docs.github.com/en/actions/reference/security/secure-use) and [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax). |
| observability      | OpenTelemetry   | `opentelemetry`  | Implement: trace instrumentation, exporter checks, context propagation and sampling. Avoid: leaking sensitive attributes and assuming the standalone trace SDK configures propagation. See [SDK](https://github.com/open-telemetry/opentelemetry-js/blob/main/packages/sdk-trace/README.md) and [privacy](https://opentelemetry.io/docs/security/handling-sensitive-data/).          |
| deployment         | Cloudflare      | `cloudflare`     | Implement: Workers static assets, Wrangler dry runs and scoped credentials. Avoid: deploying stale output, treating a dry run as deployment, or exposing secrets in assets. See [static assets](https://developers.cloudflare.com/workers/static-assets/) and [API tokens](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/).                            |

Every page follows the complete template and evidence rules in `CLAUDE.md`. For entries without a published page, source URLs, current versions, maturity/radar labels, licensing, pricing, and detailed Avoid guidance remain to be verified during authoring.
