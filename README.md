# Dev in 2026

A practical handbook for building, shipping, and operating software.

## Requirements

- Bun 1.3.10
- Node.js 22.23.4 or newer

Use `mise` to install the pinned runtimes, then run `bun install`.
Search uses the Pagefind index generated by `bun run build`; preview the built site to test search.
The pinned pnpm and Yarn development dependencies are used only to execute the package-manager command examples; Bun remains the project's package manager.
Set `SITE_URL` to the final HTTPS origin (without a path) when building for publication. Canonical URLs, RSS feeds, and the sitemap are omitted with a warning until it is set. For Cloudflare Workers Builds, add `SITE_URL` under the Worker's **Settings > Build > Build Variables and Secrets**, then trigger a new build. The local `.env` file is not sent to Cloudflare.

Use `bun run build` as the Cloudflare build command and `bunx wrangler deploy` as the deploy command. Workers Builds reads the pinned Bun version from `package.json` and the Node version from `.node-version`; see [Cloudflare's build image documentation](https://developers.cloudflare.com/workers/ci-cd/builds/build-image/).

For local builds, set the production origin in the ignored `.env` file; `.env.example` contains placeholders. Cloudflare Workers Builds can deploy automatically through its Git integration without a local API token. The separate GitHub Actions deployment workflow is manual-only; if used, it requires `SITE_URL` as a variable and `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` as secrets in GitHub's `production` environment. Cloudflare's automatic deployment does not wait for that workflow.

Analytics is disabled by default. To enable the self-hosted Umami integration in [ADR-0001](docs/adr/ADR-0001-analytics.md), place a verified tracker script under `public/` and set `UMAMI_SCRIPT_PATH` to its root-relative URL, `UMAMI_HOST_URL` to the HTTPS collector origin, and `UMAMI_WEBSITE_ID` to the site's UUID. Set all three as build environment variables (or production environment variables in GitHub); these values are public, not secrets. The build rejects incomplete configuration or a missing tracker. Configure retention, security, and privacy notices for the deployment before enabling collection.

Enable Renovate and protect the main branch with the CI verification job as a required check. Patch updates can then automerge only after checks pass; minor updates remain reviewable. The release-age cooldown depends on timestamps provided by each package source.

## Stack bootstrap

The home-page stack builder can download a Node.js, PowerShell, or POSIX shell bootstrap script. Select a primary frontend, API framework, or language/runtime when choosing multiple options in those categories. All three script formats require Node.js; frontend generation also requires npm, internet access, and a Node.js version supported by the selected framework.

Run the downloaded script from the directory in which the new project should be created, optionally passing a project name (letters, numbers, underscores, and hyphens only). It refuses to overwrite an existing directory. The script creates independent starters for the primary frontend and API; install their dependencies and follow the generated README to configure the remaining selections. It does not connect services, provision accounts, or configure authentication, deployment, or credentials.

## Commands

| Command                  | Purpose                                                                                      |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| `bun run dev`            | Start the Astro development server                                                           |
| `bun run build`          | Build the static site and Pagefind index                                                     |
| `bun run check`          | Run Astro, TypeScript, and Biome checks                                                      |
| `bun run test`           | Run unit tests                                                                               |
| `bun run test:e2e`       | Run Playwright end-to-end tests                                                              |
| `bun run snippets`       | Type-check and run snippet packages                                                          |
| `bun run verify:content` | Validate frontmatter, required headings, snippet references, and report staleness            |
| `bun run stale-report`   | Report stale or explicitly unverified tools (`--check-versions` also checks release sources) |
| `bun run links`          | Check links with lychee after building the site                                              |

See `CLAUDE.md` for content requirements and project decisions.
