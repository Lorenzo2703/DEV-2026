## What it is, when to use it, when not to

OpenTelemetry provides APIs, SDKs, and protocols for producing and transporting telemetry. Use it when you need correlated traces, metrics, and logs across services without binding all instrumentation to one backend.

Instrumentation and storage have cost and privacy implications. A small isolated application may need only straightforward logs and metrics; introduce tracing where it answers operational questions.

## Prerequisites and versions

This guide covers the JavaScript trace SDK **3.1.1** with API **1.10.0**. The SDK package requires Node.js **22.15.0 or newer**. Other OpenTelemetry language packages and experimental packages use their own version numbers.

## Install and minimal setup

Install `@opentelemetry/api` and `@opentelemetry/sdk-trace` in a Node.js project. The example uses an in-memory exporter so it can be tested locally without a collector or credentials.

This is a test setup, not a production exporter. For a service, initialize an appropriate Node SDK and exporter before instrumented libraries, configure a collector or backend, and ensure the SDK shuts down cleanly. The standalone trace SDK does not configure automatic instrumentation, context management, or cross-service propagation by itself.

## Integrate with the rest of the stack

Use the [TypeScript guide](/tools/languages-runtimes/typescript/) for type checking. For distributed traces, propagate context across service boundaries and verify that downstream spans share the expected trace. Coordinate exporter, collector, and backend configuration with your deployment.

## Test it

Run `bun run snippets` in this repository. The example is type-checked and executed with Node.js, then verifies its exported span. Add integration tests for your actual exporter, collector, and propagation configuration; an in-memory test cannot validate a remote pipeline.

## Security and performance

Do not record credentials, tokens, or unnecessary personal data in span attributes or exceptions. Review automatic instrumentation and collector processors for sensitive fields. Sampling, batching, retention, and backend limits affect both visibility and cost; measure dropped spans as well as export failures.

## Common mistakes

Avoid creating spans without ending them, initializing instrumentation too late, or assuming a standalone provider automatically propagates context. Avoid interpreting unsampled traces as proof that no error occurred.

## Observability

Monitor exporter failures, dropped spans, collector health, and backend ingestion. Check that representative requests produce connected traces and correlate them with service errors and latency.

## Upgrade and migration notes

Review the JavaScript SDK migration guide before a major upgrade. SDK 3 replaces the older trace-base package with `@opentelemetry/sdk-trace`; API and SDK versions have separate compatibility constraints. Test exporters and instrumentation together and retain a working lockfile.

## Alternatives

Structured logs and service metrics may be sufficient for a small service. Vendor-specific agents can reduce setup effort, but evaluate portability, data handling, and cost before adopting them.
