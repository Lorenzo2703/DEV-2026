## What it is, when to use it, when not to

Next.js is a React framework with file-based routing and multiple rendering options. Consider it for React applications that need server rendering, route handlers, or a mixture of static and dynamic pages.

For content-led sites with little client-side interaction, a static-first framework such as Astro may be simpler. Static export also limits which Next.js features are available.

## Prerequisites and versions

This guide uses Next.js **16.4.6** and React. The official installation guide requires Node.js 20.9 or later; check the current compatibility requirements before upgrading.

## Install and minimal setup

Use the [official installation guide](https://nextjs.org/docs/app/getting-started/installation) to create a project with `create-next-app`. Run its development server and open the local address it prints.

Layouts and pages are Server Components by default. Add Client Components only where interactivity or browser APIs require them. Decide caching and invalidation deliberately for each data boundary; the current caching documentation distinguishes Cache Components from the previous model.

## Integrate with the rest of the stack

Use the [Node.js](/tools/languages-runtimes/nodejs/) runtime for server deployment or a static host for a static export. Add a [TypeScript](/tools/languages-runtimes/typescript/) project for typed application code. A static export cannot use features requiring a running Next.js server.

## Test it

Run `bun run snippets` to build this example and check the exported HTML. This verifies a static route, not server-side authentication or dynamic rendering; test those separately in a deployed-like environment.

## Security and performance

Authorize sensitive operations on the server, validate external input, and keep secrets out of client bundles and exported HTML. When self-hosting a server, follow the official reverse-proxy guidance. Measure the effect of client components and caching on real workloads.

## Common mistakes

- **Sending private data to a Client Component:** anything passed to the browser must be treated as exposed.
- **Assuming static export supports server features:** check deployment requirements before choosing an output mode.
- **Caching user-specific data without a clear boundary:** confirm isolation and invalidation behavior.

## Observability

Monitor build failures, request errors and latency on server deployments, and client-side performance. Include release identifiers in deployment telemetry without logging secrets.

## Upgrade and migration notes

Review the [16.4.6 release notes](https://github.com/vercel/next.js/releases/tag/v16.4.6) and migration guidance before updating. Test rendering, caching, routing, and the hosting configuration together.

## Alternatives

[Astro](/tools/frontend/astro/) is a strong choice for content-first static sites. A client-only React application can be simpler when a server-rendering framework is unnecessary.
