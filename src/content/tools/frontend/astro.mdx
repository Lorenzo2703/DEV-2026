## What it is, when to use it, when not to

Astro is a web framework suited to content-focused sites. It can prerender pages to HTML and add interactive components where they are needed.

Choose static output for content that can be generated during a build. If every request requires highly dynamic, personalized data, evaluate on-demand rendering and hosting requirements, or a framework designed around your application's interaction model.

## Prerequisites and versions

This guide is verified against Astro **7.4.11**. Astro's installation guide requires Node.js **22.23.4 or newer** and excludes odd-numbered Node releases. This repository also uses Bun as its package manager.

## Install and minimal setup

Follow the [official installation guide](https://docs.astro.build/en/install-and-setup/) to create a project, then start its development server. Add a page under `src/pages` and run the project's build command to generate static output.

Use the [TypeScript guide](/tools/languages-runtimes/typescript/) for type checking and the [Bun guide](/tools/package-management/bun/) for reproducible installs. For static hosting, deploy the generated output; on-demand rendering requires a compatible deployment adapter and environment.

## Security and performance

Anything rendered into a static page is public, even if it came from a build-time environment variable. Keep secrets server-side and out of generated HTML. Validate untrusted data and review any use of raw HTML. Limit client JavaScript to necessary interactions and measure real pages.

## Common mistakes

Do not assume static content updates without a rebuild, or assume a component is interactive without client-side code. Do not select an adapter for a purely static deployment unless your hosting setup actually needs it.

## Observability

Track build and deployment failures in CI. Monitor availability and user-facing performance at the hosting layer; static output alone does not provide application telemetry. For on-demand rendering, also monitor server errors and latency.

## Upgrade and migration notes

Review the Astro release notes and the migration guide before a major upgrade. Test integrations, generated routes, and browser behavior together, and retain a known-good lockfile for rollback. Astro 7 upgrades Vite, so check Vite-dependent integrations for compatibility.

## Alternatives

A conventional single-page application can be a better fit for a heavily interactive application. Other static site generators may be simpler for a project that does not need Astro's component or island model; compare their deployment and content workflows against your requirements.
