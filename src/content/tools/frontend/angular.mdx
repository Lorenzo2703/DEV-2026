## What it is, when to use it, when not to

Angular is a framework for component-based web applications with integrated routing, dependency injection, and forms. It suits teams that value shared conventions across a substantial application.

For a small static content site, its application framework may be more machinery than necessary. Choose based on team experience and the application's interaction requirements.

## Prerequisites and versions

This guide uses Angular **22.2.6**. Angular 22 supports specific Node.js, TypeScript, and RxJS ranges; check the [compatibility table](https://angular.dev/reference/versions) before creating or upgrading a project. In particular, Angular 22 requires TypeScript 6.0 rather than this handbook's TypeScript 7.

## Install and minimal setup

Follow the [installation guide](https://angular.dev/installation) to install the CLI, create a project with `ng new`, and start the generated application. Use the versions supported by your chosen Angular release rather than upgrading TypeScript independently.

## Integrate with the rest of the stack

Use the official router for navigation and Angular's dependency injection for shared services. Choose reactive or template-driven forms according to the application's needs, and validate data again at the server boundary.

## Security and performance

Treat user input and API responses as untrusted, enforce authorization on the server, and avoid bypassing Angular's sanitization without a reviewed reason. Measure bundle size and runtime behavior; do not assume server rendering or client rendering is always faster.

## Common mistakes

- **Ignoring version compatibility:** unsupported compiler or runtime versions can break builds.
- **Trusting client validation alone:** validate and authorize on the server too.
- **Bypassing sanitization indiscriminately:** doing so can expose users to unsafe content.

## Observability

Monitor build failures, application errors, navigation failures, and user-facing performance. Redact sensitive values from client and server logs.

## Upgrade and migration notes

Review the [22.2.6 release notes](https://github.com/angular/angular/releases/tag/v22.2.6) and compatibility table before upgrading. Upgrade related Angular packages together and test routing, forms, and deployment behavior.

## Alternatives

[Next.js](/tools/frontend/nextjs/) offers a React-based application framework; [Astro](/tools/frontend/astro/) is a strong option for content-first sites. Compare ecosystem fit and team requirements rather than assuming one framework is universally better.
