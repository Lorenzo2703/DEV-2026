## What it is, when to use it, when not to

Pulumi manages infrastructure using general-purpose languages and provider SDKs. Choose it when language tooling and abstractions benefit the team; a declarative configuration language may be simpler for straightforward stacks.

## Prerequisites and versions

This guide covers Pulumi CLI **3.276.0**. Select a supported language runtime, provider, and state backend before building shared infrastructure.

## Install and minimal setup

Install the CLI and language SDK, create a small project, and inspect the preview before applying resources.

## Correct implementation

Keep stacks and configuration explicit, store secrets using the configured secrets provider, and separate reusable components from environment-specific values.

## Integrate with the rest of the stack

Run previews and tests in CI, use protected credentials for updates, and treat state backend access as privileged infrastructure access.

## Test it

Use previews, unit tests for component logic, and an isolated cloud account for integration checks. Test stack export and recovery.

## Security and performance

Protect state and secrets, pin SDK and provider versions, and review language dependencies as part of the infrastructure supply chain.

## Common mistakes

Avoid placing secrets in ordinary configuration, running updates with broad developer credentials, or hiding resource changes behind complex abstractions.

## Observability

Track previews, deployments, drift, provider failures, and state-backend health.

## Upgrade and migration notes

Review CLI, SDK, runtime, and provider release notes together; test state compatibility before upgrades.

## Alternatives

OpenTofu and Terraform use declarative configuration and have distinct licensing and ecosystem trade-offs.
