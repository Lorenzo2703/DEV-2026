## What it is, when to use it, when not to

Traefik is an application proxy that can discover services and route requests. Use it when dynamic service discovery or integration with container platforms is useful; avoid introducing a proxy layer without an operational need.

## Prerequisites and versions

This guide covers Traefik **3.7.19**. Choose the deployment provider and determine how TLS certificates and routing configuration will be managed.

## Install and minimal setup

Select a supported installation method, configure one test route, and verify TLS and backend health before exposing production traffic.

## Correct implementation

Keep provider access scoped, define TLS and routing explicitly, and protect administrative interfaces. Store sensitive configuration outside public service labels and repositories.

## Integrate with the rest of the stack

Coordinate route ownership with the platform that discovers services. Make health checks, timeouts, and upstream behavior consistent with application expectations.

## Test it

Check intended host routing, TLS, redirects, and denial of unrecognized traffic. Automated tests are intentionally omitted.

## Security and performance

Use secure TLS settings, restrict management access, and review middleware that changes request or response behavior. Monitor resource and connection limits.

## Common mistakes

Avoid exposing dashboards, accepting overly broad routes, or trusting container metadata from untrusted workloads.

## Observability

Monitor request status and latency, backend health, certificate renewal, and proxy errors.

## Upgrade and migration notes

Review release notes for configuration and provider changes; validate routes in a staging environment before upgrading.

## Alternatives

Caddy emphasizes straightforward web serving and HTTPS; platform-native ingress may be preferable when already standardized.
