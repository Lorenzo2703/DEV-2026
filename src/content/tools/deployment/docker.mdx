## What it is, when to use it, when not to

Docker provides tooling and products for building and running containerized applications. Use container images for repeatable packaging and deployment; avoid assuming a container alone provides a complete security boundary.

## Prerequisites and versions

This guide covers Docker Engine **29.9.3**. Docker Engine, Docker Desktop, and Compose are separate components with different release and licensing details.

## Install and minimal setup

Install a supported Docker product, build an image from a minimal application definition, and run it locally with only required ports and configuration.

## Correct implementation

Use multi-stage builds where useful, pin base images deliberately, run as a non-root user, and keep credentials out of image layers. Review the image contents before publishing.

## Integrate with the rest of the stack

Build and scan images in CI, publish immutable artifacts, and deploy the same artifact through environments. Define health checks and resource limits in the runtime platform.

## Test it

Check that the built image starts, serves expected traffic, and does not contain build-time secrets. Automated tests are intentionally omitted.

## Security and performance

Keep the daemon and host patched, restrict access to the Docker socket, and minimize image contents. Treat access to the daemon as privileged.

## Common mistakes

Avoid running as root without need, using mutable production tags, or mounting sensitive host paths into untrusted containers.

## Observability

Monitor container restarts, resource use, image vulnerabilities, and deployment health.

## Upgrade and migration notes

Review release and compatibility notes for the engine, Compose, and related tooling separately.

## Alternatives

Podman offers a daemonless container workflow; Kubernetes or managed container services may handle orchestration when needed.
