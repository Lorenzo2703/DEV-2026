## What it is, when to use it, when not to

Ollama runs models locally and provides APIs for applications. Use it when local control or development convenience matters; choose hosted inference when hardware, operations, or model requirements make local serving impractical.

## Prerequisites and versions

This guide covers Ollama **0.40.16**. Check model requirements against available memory, storage, accelerator support, and expected concurrent requests.

## Install and minimal setup

Install the official application, select a model appropriate to the task and hardware, and try it locally before connecting an application.

## Correct implementation

Call the documented API from a backend service, set explicit timeouts and resource limits, and handle unavailable models and failed requests. Keep model selection configurable.

## Integrate with the rest of the stack

Use an application adapter or OpenAI-compatible client only after checking its supported features. Separate local inference from hosted model credentials and billing.

## Test it

Evaluate representative prompts and outputs, measure latency and memory use, and verify application behavior when the model server is stopped.

## Security and performance

Keep local API access bound to trusted interfaces unless remote access is deliberately secured. Treat prompts and model outputs as potentially sensitive and untrusted.

## Common mistakes

Avoid exposing an unauthenticated local server to a network, assuming every model behaves alike, or estimating hardware needs from model size alone.

## Observability

Monitor model load failures, request latency, memory and accelerator use, and hosted token usage where applicable.

## Upgrade and migration notes

Review Ollama release notes and model changes separately; record model identifiers so deployments are reproducible.

## Alternatives

Hosted inference APIs reduce local infrastructure work; other local runtimes may better fit specialized hardware or deployment constraints.
