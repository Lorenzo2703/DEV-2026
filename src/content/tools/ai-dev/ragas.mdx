## What it is, when to use it, when not to

Ragas provides evaluation methods for AI applications, including retrieval-augmented generation. Use it to compare controlled experiments; do not treat an automated score as ground truth or a replacement for human review.

## Prerequisites and versions

This guide covers Ragas **0.4.3**. Evaluation methods may require model-provider access, representative test data, and additional dependencies.

## Install and minimal setup

Create a small, versioned dataset of representative questions, contexts, and expected evidence before selecting metrics.

## Correct implementation

Choose metrics that map to a product requirement, document their assumptions, and keep the dataset fixed when comparing changes. Inspect failures and examples, not just aggregate scores.

## Integrate with the rest of the stack

Run evaluations alongside application tests and record the model, prompt, retrieval configuration, and dataset version for each result.

## Test it

Check metric behavior on known-good and known-bad examples, assess score variance, and compare automated results with expert judgments.

## Security and performance

Evaluation data may contain sensitive prompts or documents. Use approved datasets, control provider access, and account for model calls and processing cost.

## Common mistakes

Avoid optimizing to a single metric, comparing scores across different datasets, or claiming statistical significance from a small sample.

## Observability

Track evaluation runs, dataset and model versions, score distributions, failed examples, and evaluation cost.

## Upgrade and migration notes

Review release notes for metric or dataset API changes and rerun a fixed baseline before adopting a new version.

## Alternatives

Human review, custom task-specific tests, and other evaluation frameworks can complement Ragas; select methods that measure the behavior users need.
